# NBN API — Claude Guide

FastAPI backend for the NBN fantasy basketball league. Runs as a systemd service on port 8001, proxied through nginx at `nbn.today/api/`.

## Source & data

- **Code:** `main.py` (app setup only) plus `routers/` (about 90 modules), `picks_conveyance/`, `stats_build/`, one-off and timer scripts at the root
- **`routers/transactions.py` and `routers/txn/`:** the transaction system is
  split. `routers/txn/` holds the models (`models.py`) and the pure pick,
  contract and cap rules (`picks.py`, `rules.py`); everything that reads data
  through a loader stays in `transactions.py`, which re-imports every `txn`
  name. **Only move a function into `txn/` if nothing it reaches is patched by
  a test on the transactions module** (tests stub data that way, and a moved
  function would read live data under the stub). `tests/test_txn_package.py`
  enforces it; `routers/txn/__init__.py` explains it. `rulebook_coverage.py`
  scans the two as one call graph. When grepping for a validator or check, grep
  `routers/` rather than one file
- **Data directory:** `/var/lib/nothing-but-stats/` — all JSON and CSV files live here. Build output is under `derived/`; league state (rosters, picks, bios, ledger) sits at the root
- **What nginx serves:** `$NBS_DATA_DIR/public`, a symlink view over both, regenerated by `nbn-today/build/link-public.sh` at the end of every build. The site repo holds no data symlinks any more (2026-08-18)

## This box: read before running anything heavy

The production server (`hostname` is `pallet`) serves nbn.today, dev.nbn.today,
pdc.nbn.today and other sites to real users, and it is small. This covers two
things: **code you write that will run there** (the API, timers, build scripts,
skills), wherever you write it, and **commands run on that machine**. Keep this
section the same in `nbn-today/CLAUDE.md`, `nbn-api/CLAUDE.md` and
`~/.claude/CLAUDE.md`.

- **1 CPU core, 1.9 GB RAM, 2 GB swap.** Never assume more. No `-j N`, no
  worker counts from `nproc` or "cores minus one", no parallel test runners, no
  pools bigger than 1.
- **Headroom is a few hundred MB.** The NBN API alone holds about 1 GB (RAM plus
  swap), and each Claude session takes 200 to 700 MB.
- **The sites are protected, your job is not.** systemd gives `nbn-api` and
  `nginx` top CPU/IO weight, a memory floor and a low OOM score, and runs
  everything in a login or Claude session at low CPU weight. So the OOM killer
  picks your job first.

Writing code that runs there:

- **Budget memory like it's scarce, because it is.** Everything the API keeps
  in memory is held for as long as it runs. Before caching a whole data set,
  measure it: one full copy of the raw box scores as `csv.DictReader` dicts is
  about 250 MB. Keep compact forms (tuples, interned strings, only the columns
  used), bound every cache, and keep one version of a rebuilt index, not two.
- **Stream big files** instead of reading them whole when you only need a pass.
- **One worker, one thread pool.** A script, skill or service that picks a
  worker count picks 1. Never size anything from `nproc`.
- **Timers stay light and spread out.** Don't schedule a new heavy job on the
  hour next to the existing `nbn-*` timers (`systemctl list-timers`).

Running commands there:

- **Run heavy work through `lowprio`** (`~/.local/bin/lowprio <cmd>`): builds,
  test suites, image or asset conversion, backfills, scrapers. It caps the job
  at 700 MB RAM and 256 MB swap at the lowest priority; past the cap the job is
  killed, not the server. Raise it (`LOWPRIO_MEM=1G lowprio …`) only when
  `free -m` shows the room.
- **Check `free -m` first.** If "available" is under 300 MB, don't start a heavy
  job; say so instead.
- **One heavy job at a time.** Don't background a build and start another.
- **A job that hits the cap needs to get lighter** (stream, batch, one worker),
  not a bigger cap.
- **Never stop, restart or reconfigure** `nbn-api`, `nginx` or another site's
  service to free memory.
- `nbn-box-health.timer` (`nbn-api/check_box_health.py`) posts to #nbn-today
  when RAM runs short or the API slows down.

**Edit in `-dev`, run ops in live.** Every `systemctl`, journal and manual-script
command in this file genuinely means live and stays pointed there.

```bash
cd ~/projects/nbn-api-dev            # edit on a branch, push, merge to main
venv/bin/python -m tests.run_all     # nothing starts a server; off the box, live-data modules skip by name
cd ~/projects/nbn-api && ./deploy.sh # ff-only, refuses a dirty tree, restarts, verifies
```

A fresh dev checkout needs its own venv, which `requirements.txt` pins exactly
(regenerate with `venv/bin/pip freeze`):

```bash
python3 -m venv venv && venv/bin/pip install -r requirements.txt
```

**There is deliberately no second API instance**, and standing one up is not the
shortcut it looks like — the reasoning is in `nbn-today/docs/dev-deploy-setup-spec.md`
under "No second API instance". In short: `.env` holds the bot token and eight
real channel ids, so a dev instance posts real embeds to `#transactions` for
every test transaction (the 300s freshness gate does not help — a dev test
transaction *is* fresh), and `roster_log_relay` starts a 60s poller at startup
whose cursor lives in the data dir, so a copied cursor relays real messages into
the real `#roster-log` a second time. Six modules also hardcode the live site
path, two of which *execute* things there.

What covers API work instead: the test suite, the read-only `/api/validate/*`
endpoints, and deploy-then-verify on live, where the restart is the gate.
`dev.nbn.today` proxies to **this** API, so a write path exercised from a dev
page is a real write.

## Service management

```bash
sudo systemctl restart nbn-api
systemctl status nbn-api
journalctl -u nbn-api -f          # live logs
journalctl -u nbn-api -n 50       # last 50 lines
curl -s https://nbn.today/api/health   # liveness: 200 {"status":"ok"}
```

`GET /api/health` is public and unauthenticated. `Restart=always` on the unit
covers a crash; health covers the case it can't — a process still answering
having lost `NBS_DATA_DIR` underneath it, which turns every roster, bio and cap
read into nonsense rather than an error. It answers **503** in that case, so a
monitor that only reads status codes catches it too. Pinned by
`tests/test_health.py`.

## Auth

Bearer token, one per member, stored as `token` on the member in
`members.json` (there is no `tokens.json`; `load_tokens()` is a shim that
reads members). `get_token_info`, `has_role`, `require_role`,
`require_any_role` and `require_admin` are in `routers/auth.py`.

Roles are `VALID_ROLES` in `routers/constants.py` (admin, rosters, bod,
curator, stats, bookie, the PDC roles, streamer, trc, trc_head, updates and
one per team); `ROLE_IMPLIES` adds the roles a role carries (bod implies
rosters and curator). `admin` satisfies every check except a TRC ballot. What
each role may do is the Roles table in nbn-today's CLAUDE.md. A role name not
in `VALID_ROLES` is refused when a member is created or edited.

`POST /api/tokens` (admin) creates or updates a member and returns the token:

```bash
curl -X POST https://nbn.today/api/tokens \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Name", "roles": ["rosters"]}'
```

A missing token is a 401 and a token without the role is a 403; pages sign
a member out only on 401. The `.nbn.today` session cookie is honoured on a
narrow allowlist only (`GET /api/auth/me` and `/api/fa/*`): read
`docs/members-and-money.md` § Browser sessions before widening it.

## Key design notes

- All writes are synchronous; no database. Concurrent writes to the same file are guarded by `_txn_lock` and `_picks_lock` threading locks.
- `player-bios.json` is the source of truth for all player identity and contract data. Roster CSVs only store `SLUG`; everything else is joined from bios (and OVR from `ovr-history.json`) at render time. Transaction handlers that rewrite a roster row (`_apply_sign` etc.) write a bare `{"SLUG": ...}` — any other key is dropped on write (`extrasaction="ignore"`), so don't rely on a roster CSV carrying anything beyond `SLUG`.
- Dead cap lives in `{team}-deadcap.csv` (one row per released player, one column per season), so a player can carry dead money on one team while playing for another. A release sets the bio's `type` back to `""`. 27 bios still carry the legacy `type: "dead"`; `migrate_dead_type.py` reports them and clears the safe ones.
- OVR history is separate from bios: `ovr-history.json` keyed by slug, each value a list of `{date, ovr}` entries.
